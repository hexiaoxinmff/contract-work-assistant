# 合同检查与制作助手使用与后期更新指南

适用版本：v2.2 试用版。本文是用户指南，不是法律审核标准。技能有更新时，请优先查看包内版本号和随包更新记录。

## 一、开始使用

1. 在支持技能或等效指令包的 AI Agent 新会话中启用“合同检查与制作助手”，先问：“请告诉我当前加载的技能名称和版本号。”
2. 用一句话说要做什么，并提供必要的合同、模板、参考材料或明确要求。建议直接把文件附加到当前会话；如果只给本机路径，Agent 必须先确认自己能访问该路径，不能访问时请用户上传，不得改用其他相似文件。
3. 上传或处理真实合同前，先按单位的数据和 AI 使用规定确认是否允许；未确认时先用虚构或已脱敏材料测试。

可以这样说：

- **文字/格式检查**：“请检查这份合同的错别字、金额日期一致性和 Word 字体字号。列出检查范围、原文位置与依据；模板没规定的格式差异只作为建议，不要修改原件。”
- **内容核对**：“请按合同文本和我提供的核对清单，逐项核对主体、期限、金额、付款、责任和附件。分别列出明确冲突、材料缺失和待确认，不要推断法律效力。”
- **按模板填写**：“请用这份模板，把甲方名称替换为……、租金替换为……，缺失信息留【待确认】。保留模板格式，另存为新文件并列明改动。”

无需学习特殊提示词；信息不足时，助手应只追问完成当前任务所必需的信息。如果任务需要使用单位模板而本次尚未提供，可以直接上传当前版本；助手按当前任务使用模板，不将其写入公开技能包；平台是否留存取决于平台实际情况。若同时有 DOCX 和 PDF，说明哪个是编辑底稿、哪个是视觉参考。

多份合同和配套文件一起处理时，先列清文件和读取范围，再按用户指定字段跨文件核对。扫描 PDF 只有在当前环境有 OCR 能力时才可读取；旧版 `.doc` 只有在环境有只读解析能力时处理。文本相似或文件名相近不等于版本一致。用户要求不存储时，不转换、另存或导出识别文本；遇到必须落盘的工具应停止并说明。

## 需要时，可以补充什么？

平时不用一次准备齐。你直接说现在想做什么，助手会根据任务提醒；已经提供过的信息不必重复。

| 你要做的事 | 可以按需提供的内容 | 暂时没有时 |
|---|---|---|
| 检查错字或内容 | 本次合同；有特别关注的地方可以顺便说 | 先检查实际读到的内容，并说明范围 |
| 看看与规定或模板有何不同 | 本次合同、当前使用的模板或核对要求 | 可先检查合同内部，无法声称已完成模板对照 |
| 按模板做合同 | 本次使用的模板，以及已确认的双方、金额、期限等信息 | 缺项标【待确认】；没有模板时不冒充单位模板 |
| 比较合同或报价 | 要比较的资料，以及希望比较的内容、计价单位或范围 | 先比已有资料，缺失条件单独列出 |
| 调整助手的工作方式 | 用自己的话说关注点、希望结果怎么展示；有条件时给获准使用的空白模板或脱敏样例 | 助手按本次已知要求处理，需要时再补充 |

示例：“这份先帮我看金额和日期，问题按位置列给我。”“以后这类任务我希望先看到待确认事项。”是否能在以后的新会话中保留这些偏好，取决于当前平台的上下文、保存能力及你的授权；不确定时请在新任务中重新说明。

真实合同、业务材料或个人信息是否可以交给当前 AI 平台处理，以所在单位的规定及平台实际数据处理方式为准。助手不会把你本次提供的资料写进公开技能包，但不能保证 AI 平台不保留上传文件、会话或日志；如要求平台完全不留存，而这一点无法确认，应暂停处理。

## 结果怎么看得更直观？

你可以直接说“用表格告诉我哪些有问题”“把两份合同左右对照一下”。助手会根据可读取的材料，用状态表或对照表列出原文位置、差异和待确认内容；看不到的部分会标明未检查。

如果需要报价柱状图或日期时间轴，也可以直接说。只有比较条件或日期信息足够清楚时才画；条件不足时会先说明缺什么。能否直接生成图片或文件，取决于当前平台可用的工具和资料处理限制。

## 绘图前的环境检查

当你让助手生成报价图或时间轴时，它会先检查当前是否能绘图。确实缺少依赖且平台及你的当前要求允许时，可以在合适的运行环境中安装必要依赖，然后验证是否可用；完成后应告诉你实际安装的内容、版本、位置和结果。若你不希望改变环境，直接说“不要安装软件”，助手就应使用已有工具或改用表格。安装失败时，它应说明情况，不影响能完成的其他工作。

## 二、文件工具能做什么

技能包内含七个脚本、大白话提示词库和虚构验收案例集。提示词库包含常见需求示例、转换骨架以及何时直接执行/何时只返回提示词的判断方法；验收案例用于按需验证自然语言理解和文件处理边界。

1. `tools/check_environment.py`：首次使用时检查 Python 版本、标准库、随包脚本是否齐全，并可选验证 DOCX 可读性及输出目录临时写入权限。脚本不会安装软件或更改权限。
2. `tools/inspect_docx_format.py`：读取 DOCX 中指定段落的 run 直接格式、样式继承链、docDefaults 和源文件哈希。
3. `tools/fill_docx.py`：只按用户明确给出的文本替换项修改 DOCX，并另存为新文件；源文本缺失、重复或被拆分到多个 run 时会停止，不能强行替换。
4. `tools/compare_docx.py`：列出原件和输出的文字差异，并检查文档包和非文字结构是否保留。
5. `tools/find_docx_occurrences.py`：在正文段落中定位重复文字，列出上下文及源文件哈希；不覆盖页眉页脚等所有部件。
6. `tools/compare_service_text.py`：比较两份 TXT/DOCX 的文字差异，标题匹配只是对照线索。
7. `tools/compare_price_inputs.py`：对已核实的结构化报价作有限换算并提示条件差异，不自动读取报价或推断实际总价。

调用脚本需当前 Agent 环境实际提供 Python/命令执行能力。若环境没有该能力，助手应如实说明；不得声称脚本已执行，也不得声称文件已生成或格式已验证。结构比对不等于页面视觉检查；重要文件还应在 Word/WPS 打开或打印预览核对。

工具不会判断合同是否合法，也不会自动签署、发送、提交业务系统或访问外部法律数据库。重要条款、争议或责任判断仍由经办人和专业人员复核。

## 三、后期升级

此版本是通用技能包。新版本发布时按以下步骤手动更新：

1. 从技能维护人处取得**完整的新版本 ZIP**，确认版本号和更新说明；不要只下载 `SKILL.md`，因为工具脚本也可能更新。
2. 关闭当前 Agent 客户端，找到本机当前 `contract-work-assistant` 技能目录。安装路径因平台、设备、账号和配置而异；按所用平台的官方说明定位，不要猜路径。找不到时请维护人协助定位，不要猜路径。
3. 将旧的整个 `contract-work-assistant` 文件夹备份到当前技能目录之外，标注旧版本号和日期，以便需要时恢复。
4. 用新 ZIP 中完整的 `contract-work-assistant` 文件夹替换当前文件夹内容，包含 `SKILL.md`、`tools/` 和 `references/`；不要只覆盖同名文件或把新旧文件夹叠加，以免遗留旧脚本。
5. 重新打开 Agent 客户端并新建会话。让助手报告实际加载的版本；如版本不是新版本，确认替换的是实际生效目录，并按平台要求重新加载技能。
6. 用虚构样例做冒烟验证：检查技能版本、运行格式检查脚本、按一项明确文本另存、再用比对脚本核对。确认输出文件和版本都正确后再开始日常试用。

升级失败时，恢复备份的旧文件夹并新建会话；不要在合同工作中途更新。技能不会自行从网络下载或覆盖新版。

如果技能是通过所用平台的官方技能市场或应用插件商店安装的，则按该发布渠道的版本更新流程操作，不要将本机文件夹更新步骤套用于平台安装。

## 四、向维护人反馈

反馈时尽量提供：技能版本、任务类型、虚构/脱敏输入、预期结果、Agent 实际回复、脚本是否真实执行及输出文件路径。不要在普通反馈中附上未经允许的真实合同或敏感个人信息。
