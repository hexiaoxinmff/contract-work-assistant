# 错别字检查与复查关口

复查是助手自己的质量控制，不是每一步都要用户确认的审批流程。按用户本次任务选择适用项；只处理用户指定范围。用户明确只要提示词时，不执行材料处理。涉及合同输出不可声称专业法律意见或无风险。

## 1. 接收和读取关口

确认本次使用的实际文件、版本、用户目标与授权，以及可读取的章节、表格和页码。文件不可访问、不是指定版本或关键部分无法读取时，不用相似文件替代；如实说明已处理和未处理范围，可先完成不依赖缺失材料的部分。对只读、不存储等要求先核实工具及平台的实际数据处理边界；不能满足时停止依赖部分。

## 2. 文字检查关口

用户要求查错字、文字检查或通读审核时，对实际读到的对应范围逐段检查错别字、漏字、多字、形近字、同音字、常见术语、标点及明显的文字不一致，并考虑上下文。不得仅用通用词表或字符匹配认定错误。人名、公司名、商标、地名、编号、特殊术语及用户明确提供的专有写法，没有可靠依据不得自行更改；不确定时标“疑似，待确认”。扫描识别疑点优先核看原始页面；无法辨认注明未能确认，不能把 OCR 错误当合同错误。

每一项复核实际原文、位置、前后语境与建议，区分明确错字、疑似问题和一致性差异；短引用仅限需要解释的部分。说明文字检查覆盖范围和未读部分。没有发现问题时说“在已检查范围内未发现明显错别字”，不承诺零错或全文已读。不要为凑数编造问题，不因为名称看似不常见就更正。

## 3. 内容与对比关口

对每个结论回查对应原文、另一份依据、位置和比较口径；区分明确冲突、正常差异、缺资料、未读和待确认。对数值换算再次核对单位、数量、期间、税费、公式与算术；脚本结果也需与来源交叉核对。不要把标注为待确认的数字写成已确认事实。

## 4. 修改与制作关口

仅按用户授权处理；在动手前核实原模板、需要替换的内容及来源，可能错误替换时暂停该部分。根据明确事实填写，缺项保留【待确认】；未经授权不修复原模板里其他错字或改动法律条款。生成后回读实际新文件，核对指定变化与填写值、缺项标记、原件保护和实际可验证的格式。使用随包精确替换工具时按技能规则运行 compare_docx 复核差异；不能声称 XML 结构、内容或版面通过，除非确实检查。若可用渲染工具并符合数据边界，核查受影响页面；不能渲染须明确视觉检查未完成，不阻断有条件的草稿交付。

## 5. 交付关口

输出前重新核对结果与用户范围、文件名/路径、每项证据、待确认和已读覆盖是否对应。依据实际情况简短说明完成了什么、未完成什么、修改了哪些内容和是否另存；文件生成失败不得报告已交付。只给用户任务需要的信息，不虚构全面检查、法律合规或视觉验收。
